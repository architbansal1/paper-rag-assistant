# trl is pinned exactly (not >=): newer trl releases added an experimental
# "chunked cross-entropy" patch to SFTTrainer that crashes on some
# PEFT+4-bit model setups with
# `AttributeError: 'functools.partial' object has no attribute '__func__'`.
# trl==0.9.6 predates that feature entirely.
#
# Everything else is left as a floor (>=), not pinned exact, on purpose:
# bitsandbytes/transformers/accelerate/torch ship CUDA-version-specific
# binaries, and Kaggle/Colab pre-install versions matched to their own
# CUDA driver. Pinning these to an older exact version, or reinstalling
# with --upgrade, can silently replace the platform's matched torch/
# bitsandbytes build with an incompatible one (seen as "Could not find
# the bitsandbytes CUDA binary", `ModuleNotFoundError: No module named
# 'triton.ops'`, or a torchcodec/ffmpeg load error after torch gets
# upgraded to a build Kaggle didn't ship). If a fresh install ever
# breaks bitsandbytes again, use `pip install --no-deps --force-reinstall
# bitsandbytes` (never --upgrade) so pip can't touch torch, and always
# recheck `python -c "import torch; print(torch.__version__,
# torch.cuda.is_available())"` right after any pip install.
